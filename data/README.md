# Data directory

This directory holds the institutional source records, human-curated decisions, and
downloaded research content used by the Research Connections Atlas pipeline. Most of
its contents are local, potentially sensitive, and intentionally excluded from Git.

Do not place credentials here; use `.secrets/` or environment variables. Before
sharing any source record, workbook, abstract, PDF, or generated dataset, complete the
appropriate privacy, rights, and publication review. See
[`docs/DATA_AND_PRIVACY.md`](../docs/DATA_AND_PRIVACY.md) for the repository policy.

## What is authoritative?

The files in this directory fall into three categories:

- **Source inputs** are original institutional records supplied to the pipeline.
- **Curated inputs** contain durable human decisions that should survive reruns.
- **Generated working files** are produced by the pipeline or review tools and can be
  rebuilt. Do not treat them as the sole record of a decision.

The tracked CSV files are the durable source of truth for faculty identity and
attribution decisions. The generated Excel review workbooks are interfaces for making
those decisions; their reviewed contents must be imported back into the CSV files.

## Directories

### `Annual-Reports/`

Local annual-report PDFs used by `code/extract_publications.py`. The extractor finds
faculty headings and publication citations, derives candidate titles, and preserves
the source report, report year, PDF page, raw citation, extraction method, confidence,
and review status as provenance.

Place annual-report files directly in this directory. The year should be present in
the filename in a form the extractor can recognize. These reports may contain
institutional or personal information and are ignored by Git. `.gitkeep` is the only
tracked file; it preserves the empty directory in a fresh checkout.

Known source limitations are documented in [`code/README.md`](../code/README.md),
including the image-only 1999 report and the irregular text layout of the 1997 report.

### `DigitalMeasure-Reports/`

Local Digital Measures-style Word (`.docx`) exports processed by
`code/extract_digitalmeasure_publications.py`. Each document is treated as a sequence
of faculty resumes. The extractor tracks the resume owner and publication subsection,
classifies records, flags ongoing work, and retains the complete citation and local
faculty evidence.

Articles, books, book chapters, and other publication-ready works may be forwarded for
metadata resolution. Presentations and ongoing work remain in the audit output but are
not sent to Crossref or OpenAlex for publication resolution. The report year is read
from the filename.

These source exports are ignored by Git. `.gitkeep` preserves the empty directory in
a fresh checkout.

### `publication_abstracts/`

Plain-text abstracts obtained during publication resolution, primarily from OpenAlex.
Files are generated by `code/resolve_and_download_publications.py` and use a stable,
collision-resistant name derived from the report year, normalized publication title,
and identifier hash.

The topic-modeling pipeline normally reads abstracts from the publication-resolution
dataset; these files preserve local copies of available abstract text. They are
generated, potentially subject to third-party terms, and ignored by Git.

### `publication_pdfs/`

Publication PDFs downloaded by `code/resolve_and_download_publications.py`. The
resolver downloads only locations identified as open access or accompanied by license
metadata; it does not bypass authentication or paywalls.

These PDFs are generated working data, may be copyrighted, and are ignored by Git.
They must not be assumed publishable merely because they were legally retrievable.

### `model_cache/`

Local Hugging Face and SPECTER2 model cache used by
`code/cluster_publications.py`. Setting the cache under `data/` keeps large downloaded
model artifacts out of the source tree and makes topic-model runs reusable across
sessions.

This directory is generated, potentially large, machine-specific, and ignored by Git.
It can be rebuilt by downloading the configured model and adapter again.

## Files

### `Annual Report compilation.xlsx`

Local source workbook containing annual institutional totals. The reconciliation step
reads the active sheet's `Year` and `Scholarly Papers Published` columns and compares
those expected totals with extracted publication-candidate counts.

Used by:

```bash
.venv/bin/python code/reconcile_publication_counts.py
```

This workbook is a source input and is ignored by Git.

### `faculty_identifiers.csv`

Curated identifiers for faculty in the institutional registry. Its columns are:

```text
faculty_id,faculty_name,orcid,source,verified_at,notes
```

`faculty_id` is the stable join key; `faculty_name` is a human-readable cross-check.
ORCIDs are normalized and checksum-validated. An identifier can strengthen identity
resolution, but it does not independently add unrelated publications to the corpus.

This is a curated, tracked input. Add identifiers only when they have been verified
and are appropriate to keep in the repository.

### `faculty_attribution_review.xlsx`

Generated human-review interface for faculty names and faculty-publication links. It
is created from the institutional registry, accepted attributions, and disambiguation
audit by:

```bash
node code/create_faculty_attribution_review_workbook.mjs
```

Its principal sheets are:

- `Canonical Faculty` for approving, renaming, aliasing, or excluding roster entries.
- `Attribution Review` for approving, removing, or replacing existing links.
- `Exceptions` for reviewing ambiguous or provisionally rejected links.

Reviewers edit only the designated yellow columns. After review, validate and import
the workbook with:

```bash
.venv/bin/python code/import_faculty_attribution_review.py --dry-run
.venv/bin/python code/import_faculty_attribution_review.py
```

The workbook is generated, ignored by Git, and **not authoritative**. The importer
writes its durable decisions to the three tracked faculty CSV files described below.

### `faculty_attribution_review_decisions.csv`

Normalized, durable log of active decisions imported from the faculty-attribution
review workbook. Its columns are:

```text
decision_id,source_sheet,target_type,target_id,action,faculty_name,replacement_value,reason,reviewer,reviewed_at
```

Decision IDs are deterministic for a reviewed target. Importing an updated workbook
upserts decisions; the `clear` review action removes a prior decision. This tracked
file is the authoritative record of workbook review decisions.

### `faculty_name_overrides.csv`

Derived, durable instructions for changing the institutional faculty registry without
changing stable faculty IDs. Its columns are:

```text
decision_id,faculty_id,action,value,reason,reviewer,reviewed_at,source
```

Supported actions are `rename`, `add_alias`, and `exclude`. The population pipeline
applies these overrides before matching citation names. This is a tracked curated
input, normally generated by importing `faculty_attribution_review.xlsx` rather than
edited independently.

### `faculty_attribution_overrides.csv`

Durable additions and removals for faculty-publication attribution. Its columns are:

```text
feedback_id,decision_id,publication_id,action,faculty_name,reason,reviewer,reviewed_at,source
```

`action` is `add` or `remove`. The attribution resolver applies these decisions after
local and OpenAlex identity evidence has been evaluated. Rows can originate from the
review workbook or from separately approved feedback. This tracked file is an
authoritative curated input.

### `publication_metadata_curation.xlsx`

Generated review workbook for correcting matched publication metadata and filling
missing abstracts. It is built from
`results/publication_resolution/publication_resolution.csv` by:

```bash
node code/create_publication_curation_workbook.mjs
```

The `Publication Curation` sheet allows edits to title, publication year, DOI, authors,
landing URL, and abstract, with optional contributor and notes fields. `work_key` and
`source_record_ids` identify the work and its source records and must not be edited.
The `Baseline - Do Not Edit` sheet lets the importer identify only cells that a human
changed.

Apply the edits with:

```bash
.venv/bin/python code/apply_publication_metadata_curation.py
```

The importer propagates a curated work to every associated annual-report record. This
workbook is local and ignored by Git. Unlike the faculty review workflow, its changes
are reapplied directly to the generated publication-resolution dataset, so preserve
the workbook locally if those edits must survive future automated resolution runs.

### `.DS_Store`

macOS Finder metadata. It is not project data and should not be relied on, shared, or
committed.

## Git and handling summary

| Path | Role | Git policy |
| --- | --- | --- |
| `Annual-Reports/` | Institutional PDF source records | Ignored except `.gitkeep` |
| `DigitalMeasure-Reports/` | Institutional Word source records | Ignored except `.gitkeep` |
| `Annual Report compilation.xlsx` | Annual count source | Ignored |
| `faculty_identifiers.csv` | Verified faculty identifiers | Tracked curated input |
| `faculty_attribution_review.xlsx` | Generated review interface | Ignored |
| `faculty_attribution_review_decisions.csv` | Durable review decisions | Tracked curated input |
| `faculty_name_overrides.csv` | Durable roster corrections | Tracked curated input |
| `faculty_attribution_overrides.csv` | Durable attribution corrections | Tracked curated input |
| `publication_metadata_curation.xlsx` | Local metadata review and corrections | Ignored |
| `publication_abstracts/` | Downloaded/generated abstract text | Ignored |
| `publication_pdfs/` | Rights-aware downloaded publications | Ignored |
| `model_cache/` | Downloaded model artifacts | Ignored |

Generated pipeline tables and web-export artifacts do not belong in this directory.
They are written under `results/` and copied, after review, to `webapp/public/data/`.
